# 0030. タスクの成果物の「出所: … 引用: 「…」」を、出所が指すファイルと照合する
- 状態: 採用 / 日付: 2026-10-03

## 状況
issue #36 の事故（12 か所）は、調査係がタスクの直下に書いた成果物の引用で起きていて、出所は references ではなく案件の knowledges だった。0028・0029 の照合は references の「引用した記述」だけを見るので、1 か所も拾えない。

テンプレートから作った実際の作業スペースで、成果物（references と index.md 以外の .md）64 本の出所の書き方を数えると、次の 5 通りだった: パス（`.md` 付き）、references のファイル名（途中で切れたものを含む）、3 桁のナレッジ番号（`009「ステップ 4」`）、「同上」、引用の次の行に書く形。

## 決定
- `deliverable_misses` が、成果物を 1 項目（箇条書き・番号・見出し・表の行で区切り、続きの行を含める）ずつ見て、`出所:` と `引用: 「…」` が両方ある項目の引用を、出所が指すファイルと照合する。照合のしかたは 0029 と同じ
- 出所の解決: 「同上」は直前の項目の出所、URL は `ref add` した reference の `source`、3 桁の番号は案件の `knowledges/NNN_*.md`、それ以外はパスか、references・knowledges のファイル名の先頭（8 字以上）。reference なら原文（`.orig.md`・`.normalized.md`）も含める
- 出所を解決できない項目（人からの聞き取りなど）と、出所の無い引用は見ない
- `know new` は現在のタスクの分を、`doctor` は doing のタスクの分を出す。完了したタスクは見ない（出所のナレッジは後で書き換わるので、当時正しかった引用が外れる）
- 調査係の定義（Claude・Codex）の出力の書式に `出所: <ファイル> 引用: 「原文のまま」` を書く。AGENTS.md は変えない

## 理由
- 事故の下書き（セッション記録から復元）に当てると、12 か所のうち 6 か所（原文と不一致 4・出所違い 2）を拾い、誤検知は 0。出所違いは、引用がもう一方のナレッジにはあるのに、書いた出所には無い、で拾える
- 同じ作業スペースの成果物の引用 410 件では「出所に無い」は 2 件で、どちらも出所のナレッジが後から書き換わった（「道具」→「ツール」）ための本物の食い違い。完了したタスクを見ないので `doctor` には出ない
- 書式は調査係の定義にだけ書く（0027）。本線の固定分は増えない

## 捨てた案
- 行全体から「」を拾う（「引用:」の目印を要らなくする）: 出所の見出しを「」で書くので（`009「動くコード 1」`）、事故の下書きだけで誤検知が 11 件出た
- 出所はあるが引用が無い項目を数える: 事故の 3 か所（引用の抜け）を拾えるが、同じ下書きで 22 項目が余計に出る（型の一覧などは引用を付けない書き方が普通）
- 完了したタスクも `doctor` で見る: 上の 2 件のように、ナレッジを直すたびに古いタスクが警告になる

## 影響
拾えないもの: 引用の抜け、原文に根拠のない言い換え（引用の外の地の文）、誇張、引用の外の誤字（事故の残り 6 か所）。出所のファイル名を書き間違えると照合されない（黙って通る）。

根拠: issue #36、`tests/test_ws.py` の `test_deliverable_quotes_checked_against_cited_source`
