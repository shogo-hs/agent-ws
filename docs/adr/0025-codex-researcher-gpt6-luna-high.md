# 0025. Codex の調査係は gpt-6-luna・high にする（0020 を置き換え）
- 状態: 採用 / 日付: 2026-10-03

## 状況
0020 で Codex の調査係を gpt-5.6-luna・max にした。その後 OpenAI は gpt-5.4-mini の置き換え先を gpt-6-luna に改め、Luna の推論量は high から始めるよう案内している（`docs/sources/codex-token-saving.md` #1）。クレジットは 100 万トークンあたり入力・キャッシュ・出力が 2.5 / 0.25 / 12.5 で、gpt-5.6-luna（5 / 0.5 / 30）の半分以下（#2）。ただし推論量の段は世代をまたいで対応しない（#1）ので、0020 の max をそのまま持ち込めない。Codex CLI 0.153.4 は gpt-6-luna を 400 で拒否し、0.156.1 以降で通る（M1）。

## 決定
`.codex/config.toml` の `[agents]` と `.codex/agents/researcher.toml` を gpt-6-luna・high にし、AGENTS.md の spawn_agent の指示も同じ値にする。README の Codex CLI の必要な版を 0.156.1 以上に上げる。`bench/researcher_effort.py` の採点の語「項目定義」を「項目」に直す。

## 理由（M2。0020 と同じ 1,134 行の文字起こしから決定 20・宿題 15 を抜き、却下・検討中 12 を混ぜない 47 項目。読み切り規則つき、各 n=5、Codex CLI 0.160.0、中央値）
| モデル・推論量 | 全問正解 | 入力 | 出力 | 秒 | クレジット / 回 |
|---|---|---|---|---|---|
| gpt-5.6-luna・max（0020） | 5/5 | 373,563 | 5,677 | 127 | 0.550 |
| gpt-6-luna・high | 5/5 | 168,377 | 2,368 | 58 | 0.142 |
| gpt-6-luna・max | 4/5（1 回は決定 4 件を落とした） | 266,977 | 5,452 | 126 | 0.211 |
- high は正答率を落とさずに、クレジット −74%・時間 −55%（5 回すべてで 0020 の条件を下回る。並べ替え検定 p=0.008）。API キーの人も単価は半分以下（#3・#4）
- max は high より高く遅いうえ、読み切らずに書いて決定を落とす回が出た。公式の出発点（high）を採る
- 採点の誤り: 6-luna・high の 5 回すべてが「山田さん：10 月 2 日までに顧客マスタの項目を定義する」と書き、照合の語「項目定義」に当たらず宿題 1 件の落としに数えられていた。中身は正しいので語を直し、今回の 15 行を採点し直した。0020 の数字は当時の採点のまま

## 捨てた案
- gpt-5.6-luna・max のまま: 正答率は同じで、クレジットは 3.9 倍・時間は 2.2 倍
- gpt-6-luna・max: 上の表のとおり
- 本線に向けて固定の指示を絞る（OpenAI の社内評価でトークン −41〜66%、#5）: Codex 本線を測る bench が無い。測れるようにしてから別に決める

## 影響
Codex CLI 0.156.1 より前の版では、調査係が 400 で落ちる（`[agents]` の既定で起動する子もすべて）。古い版のまま使う人は、config.toml と researcher.toml を gpt-5.6-luna・max に戻す（0020 の値）。Enterprise と Edu では、管理者が Luna を有効にするまで使えない（#1）。Claude Code 側の haiku は変えない。n=5 なので、Luna が更新されたら #1 を撮り直して測り直す。
