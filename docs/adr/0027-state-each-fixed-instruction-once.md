# 0027. 毎ターン送る固定の指示は 1 か所にだけ書き、オントロジーの使い方は定義があるときだけ注入する
- 状態: 採用 / 日付: 2026-10-03

## 状況
AGENTS.md・スキルの name と description・SessionStart の注入・researcher の定義は、毎ターン同じものが送られる（固定分）。OpenAI の GPT-6 のガイドは「指示は 1 回だけ書く」と勧め、固定の指示を絞った構成でトークンが 41〜66% 減ったと書いている（`docs/sources/codex-token-saving.md` #5。システムプロンプト全体を絞った社内評価）。agent-ws の固定分を部品ごとに外して測ると、agent-ws が変えられるのは全体の約 3 割だけだった（`bench/fixed_parts.py`）。

| 部品（1 ターンのトークン） | Claude sonnet | Codex gpt-6.1-sol |
|---|---|---|
| 固定分の全体 | 18,822 | 17,380 |
| AGENTS.md | 4,049 | 3,269 |
| スキルの name・description | 669 | 654 |
| SessionStart の注入 | 1,277 | 997 |
| researcher の定義 | 121 | 533 |

## 決定
2 か所以上に同じことが書いてある行と、エージェントの行動を変えない説明（hook の仕組み・計測値・人向けの注意）を削る。正誤に効く指示は触らない。

| 削ったもの | 削っても困らない理由 |
|---|---|
| ルートで起動する | 起動場所は人が決める。README の導入手順と「制約と注意」にある |
| 読む順番 1 の節の列挙と「読み直さない。長すぎるときだけ Read」、ターンを減らすの「注入済みの index.md を読み直さない」 | 注入文の見出しが「Read で読み直さない」と言う。長すぎるときの注入は「まず index.md を読む」と言う |
| 読む順番 3 の「一覧は hook が差し込む」「案件側が勝つ」「中身の一覧はそこにある」、拒否対象の列挙、normalize の説明 | 共通ナレッジの注入文に「案件側が勝つ」がある（共通ナレッジが無ければ衝突しない）。拒否の詳細は拒否文に出る。「舐めない」と「hook が拒否する」は残す |
| Web の「現在のタスクがあるとき」「Codex では web_search を外してある」「再収集しないため」 | 理由は冒頭の目的と同じ。拒否文が `ref add` のコマンドを出す |
| 「hook が起動のたびに現在のタスクを差し込む」「hook が起動のたびに全行を差し込む」 | 仕組みの説明。差し込まれたもの自体が見えている |
| 見出しの 39k・3.7k、「続けて」の 1 往復の括弧 | 計測値と、見出しと同じ理由。数字は README にある |
| bench/ と docs/snapshots/ の説明、台帳の場所 | 読まない・hook が拒否する、は残す |
| transcript-ingest の「researcher の中で走る」 | スキルの frontmatter（`context: fork`・`agent: researcher`）が決める |
| 手順は各スキルにある | スキルの一覧は Claude Code も Codex も自動で載せる |
| LESSONS.md が 20 行を超えたら統合する | 超えた時点で `lesson add` と `doctor` が同じ文で知らせる |
| 注入の「他の tasks/ 配下は読まない」 | AGENTS.md の「禁止」に同じ行がある（タスクが無いときも効くのでそちらを残す） |
| knowledge-promote・ref-add の description の理由文 | AGENTS.md の「禁止」と冒頭の目的に同じことがある |

オントロジーの節（約 960 字）は削らずに SessionStart の注入へ移し、共通か今の案件に `ontology.json` があるときだけ渡す（判定は用語集の別名合流と同じ）。定義の無い利用者は毎ターン払わなくてよくなる。注入の上限（6,000 字）には数えない（もともと AGENTS.md にあった分で、足しても Codex の 8,000 字に収まる）。

AGENTS.md は 5,175 → 3,981 字、変えられる部分の計は 7,857 → 6,579 字。固定分は Claude 18,822 → 17,862（−5.1%）、Codex 17,380 → 16,591（−4.5%）。

## 理由（`bench/results/runs_trim.jsonl`・`runs_trim.summary.md`。large・各 10 回。A は削る前、A2 は削った後）
| エージェント | 実験 | 処理した入力 A → A2 | 費用 A → A2 | 正誤 A / A2 | p（入力 / 費用） |
|---|---|---|---|---|---|
| Claude sonnet | trap | 101k → 103k | 0.106 → 0.107 USD | 10/10 / 10/10 | 0.78 / 0.57 |
| Claude sonnet | newtask | 111k → 106k | 0.135 → 0.127 USD | 8/8 × 10 / 8/8 × 10 | < 0.01 / 0.04 |
| Codex gpt-6.1-sol・medium | trap | 118k → 126k | 2.11 → 2.45 cr | 10/10 / 10/10 | 0.41 / 0.18 |
| Codex gpt-6.1-sol・medium | newtask | 144k → 133k | 2.27 → 2.07 cr | 8/8 × 10 / 8/8 × 10 | 0.15 / 0.26 |

- 正誤はどの組でも落ちなかった。trap は 40 回とも正解で聞き返しも 0 回、newtask は 40 回とも必須 8 項目がそろい、古い数字を前提に使った回は 0 回（機械が拾った言及はすべて「8 台・10 台は NG」「提案書の 8 台から見直し」の形）。他タスクへの立ち入りも 0 回
- 費用に差が出たのは Claude の newtask だけ（入力 −5%、費用 −6%）。固定分の差（約 1k）× ターン数とほぼ合う。ほかの 3 組の差は、同じ A を 2 組走らせたときの揺れ（Codex trap の 1 回あたり 80k〜177k）の内側で、誤差として扱う
- OpenAI の −41〜66% は再現しない。agent-ws が変えられるのは固定分の約 3 割で、そのうち約 2 割を削っただけなので、上限でも全体の数 % になる。それでも採るのは、正誤を落とさずに毎ターンの固定分が約 5% 減り、「1 か所にだけ書く」で以後の書き足しの置き場所も決まるから

## 捨てた案
- Codex の `spawn_agent` の回避策を削る: 名前指定の効かない版で調査係が本線と同じ高いモデルで動く。trap と newtask では委譲がほぼ起きず、壊れても検出できない
- 「目的と進め方を書き、段階ごとに [x]」を task-start スキルに任せる: Claude の bench は Skill ツールを許していないのでスキル本文が読めない。進め方の更新はすべてのタスクで効く
- 「引用した記述を埋める」を ref-add スキルに任せる: chain の正誤に効く行で、今回は chain を測っていない
- 「このリポジトリ自体を直すとき」を README に移す: エージェントは README を読まない。テストを忘れる方が高くつく
- ツール定義・ハーネス自身の指示を減らす: agent-ws からは変えられない（使わないツールの deny は ADR 0021 で済み）

## 影響
AGENTS.md に書き足すときは、hook の拒否文・注入文・スキルの description・`doctor` の出力に同じことが無いかを先に見る。オントロジーを定義すると、その案件の注入が約 1,000 字増える。chain・small・Haiku・Opus では測っていない。
