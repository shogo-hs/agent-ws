# 0036. 起動したセッションは未設定で始め、コミットはそのセッションが書いたファイルだけにする
- 状態: 採用 / 日付: 2026-11-05

## 状況
同じ clone で複数のセッションを並べると、2 つ困る。新しく起動したセッションは 0003 のとおり `.ws/current`（どのセッションかに関係なく最後に設定したタスク）を引き継ぐので、`task new` を忘れると別のセッションと同じタスクに書き込む。作業ツリーは 1 つなので、`git add -A` でコミットすると他のセッションの書きかけも入る。
## 決定
- 起動（SessionStart の source=startup）では空の写し（未設定）を置き、`.ws/current` は「最後に設定されたタスク」として案内に出すだけにする。`/clear` は従来どおり引き継ぐ。
- Edit・Write・MultiEdit・NotebookEdit・apply_patch の書き先は PreToolUse の hook が、`scripts/ws` の書き込みは `write()` などが `.ws/sessions/<session_id>.touched` に記録する。
- `scripts/ws commit "<メッセージ>"` と `task done` は、タスクのフォルダと記録のうち変更のあるファイルだけを `git commit -- <パス>` でコミットし、残った変更を一覧で出す。
## 理由
hook には `session_id` と書き先のパスが届くので、ファイル単位なら追加の仕組み無しで区別できる。`git commit -- <パス>` は指定外の変更（他のセッションがステージしたものも）を入れない。
## 捨てた案
- セッションごとに git worktree を切る: 現在のタスク・ナレッジ・LESSONS.md が worktree ごとに分かれ、合流のたびに衝突を解く手間が出る。
- 行単位で区別する: `tasks/index.md` や `LESSONS.md` は複数のセッションが追記するが、どちらのコミットに入っても困らない。
## 影響
Bash（`sed` やリダイレクト）での書き換えは記録できないので、残りの一覧に出る。`task use` 後に Codex で新しいセッションを開く手順は、新しいセッションで `task use` し直す形に変わる。
