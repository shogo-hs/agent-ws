# 0020. Codex の調査係は gpt-5.6-luna・max にし、researcher に「末尾まで読み切る」規則を足す
- 状態: 採用 / 日付: 2026-09-14

## 状況
Codex 側の調査係（`.codex/agents/researcher.toml`・`[agents]` の既定・AGENTS.md の spawn_agent 指示）は gpt-5.4-mini・low だった。OpenAI は GPT-5.4 / 5.4 mini を 2026-08-31 に Codex（ChatGPT ログイン）から退役させ、置き換え先を gpt-5.6-luna と明記している（台帳 #1）。実測でも `codex exec -m gpt-5.4-mini` は 400 で拒否され、`[agents]` の既定で起動する子は全部失敗する状態だった（M1）。利用者から「gpt-5.6-luna の max などが良いのでは」と提案があった。

## 決定
モデルは gpt-5.6-luna、推論量は max（`[agents]` と researcher.toml の両方に明示。省くと luna の既定 medium になる）。researcher（Claude Code・Codex 共通の 4 行）に「長いファイルは行数を数え、末尾まで範囲を分けて全部読んでから書く」を足す。AGENTS.md の spawn_agent 指示に `fork_turns="none"` を足す（`"all"` は親の会話を丸ごと複製し、モデルの指定も効かない。M2）。

## 理由（数字は台帳の値をそのまま）
- 置き換え先は公式の指示どおり luna（#1）。$0.20 / $1.20 で 5.4 mini（$0.75 / $4.50）より安く、terra（$2 / $12）の 1/10（#3・#6）。サブスクの消費量にも同じ比で効く（#6）
- 推論量は「必要な結果が出る最低」で選ぶ（#1）ので、その結果を測った（M4。1,134 行の文字起こしから決定 20・宿題 15 を抜き、却下 12 を混ぜない 47 項目の正答率）。素の依頼文では low が 3 回とも決定 8 件を落とし（0.638 / 0.83 / 0.638。確かめた run は 520 行までしか読んでいない）、読み切り規則を足しても 8 回中 2 回は全範囲を読んだ後に grep の当たりだけで書いて「決まりました」型の決定 8 件を落とす（0.83。中央値 0.978・全問正解 4/8）。max は規則の有無を問わず 7 回すべてで決定 20 件を落とさず、最悪 0.979（宿題 1 件）、規則あり中央値 0.990。medium・high・xhigh は low と同じ落ち方をする回がある（medium 規則あり 0.894、high 素 0.638）
- max の代償は low（規則あり）比で出力トークン 3.1 倍（中央値 7,170 対 2,335）・時間 2.4 倍（159 秒対 67 秒）・API 換算 1.6 倍（0.026 USD 対 0.016 USD）。本線は調査係の成果物を確認せずに使うので、1 回 0.01 USD の差より取りこぼしのほうが高い。却下案の混入はどの条件でも 0

## 捨てた案
- low のまま（ADR 0008 の既定）: 規則を足しても決定の 4 割を落とす回が 8 回中 2 回。公式も low は「単純で速さが要るとき」（#2）で、通読して抜く仕事には足りない
- gpt-5.6-terra・low: 公式は「読む量の多い走査」向けに勧める（#2）が 0.809 / 1.0 / 0.83 で luna と同じ落ち方をし、API 換算で luna max の 3.7 倍（0.095 USD）
- gpt-5.4-mini を API キー前提で残す: ChatGPT ログインの利用者では `[agents]` の既定が黙って失敗する

## 影響
API キーで Codex を使う人も luna に揃う（API でも提供、#3）。`[agents]` の既定は本線が spawn する子すべてに効くので、調査以外の子も max になる（調査以外を委譲する用途が出たら researcher.toml だけに寄せる）。Claude Code 側の haiku は変えないが、読み切り規則は共通で入る。n=3〜8 の差なので、luna 段が更新されたら #1 を撮り直し、`bench/researcher_effort.py` で測り直す。
