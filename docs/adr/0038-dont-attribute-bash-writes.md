# 0038. Bash で書いたファイルはどのセッションのものとも決めず、タスクのフォルダはパスで決める
- 状態: 採用（0037 を置き換え） / 日付: 2026-11-05

## 状況
0037 は Bash の実行中に変わったファイルをそのセッションのものとして記録した。テストや外部コマンドの Bash は数十秒〜数分かかり、その間に他のセッションが書いたファイル（他のタスクのフォルダの中を含む）まで拾った。記録 4 つのうち 3 つに他のタスクのファイルが 8・23・8 件入り、別のセッションでは他のタスクのファイルが 3 回コミットに入って手で外した。
## 決定
- Bash の書き込みは記録しない（bash_start と PostToolUse の Bash を消す）。commit の残りの一覧に出し、自分のコマンドで書いたと分かるものだけをエージェントが `git commit -- <パス>` で足す。
- 今のタスクのフォルダはパスで丸ごと入れる。記録にある他のタスクのフォルダのファイルは、他のセッションが今そのタスクを作業していなければ入れる（`task use` で移る前の書き込み）。
- `task done` はそのセッションの記録を消す。
## 理由
先行事例で Bash の書き込みの帰属を自動で決めているものは無い。Claude Code・Codex app・Cursor は worktree で分け、GitButler の旧 Claude Code hooks 連携も Edit のパッチと重なる hunk だけを割り当てて Bash の書き込みは残していた（連携は 2026-05 に削除）。agent-ws ではタスクのフォルダが worktree の代わりになる（直近 50 コミットのファイルの 92% がタスクのフォルダの中）。誤りがすべて取りこぼし（作業ツリーに残る）の側に倒れ、Claude Code と Codex で動きがそろう。
## 捨てた案
- 記録に強弱を付けてコミット時に判定する: Codex の Bash と、自分のコミットより後に終わる相手の Bash で誤帰属が残り、複雑。
- 記録をやめ、タスクのフォルダ外の変更をすべて入れる: 他のセッションのスキルや設定の書きかけが混ざる。
- worktree に分ける: ナレッジ・LESSONS.md・.ws/ の状態が分かれ、合流の手間が出る（0003 と同じ理由）。
## 影響
Bash で直したタスクのフォルダ外のファイル（スクリプト・スキルなど。直近 50 コミットで 6 件ほど）は、自分で足さないとコミットされない。2 つのセッションが同じファイルを Edit したときは、先にコミットした側に両方の変更が入る。
