# 0005. 人からの指摘は 1 回目で LESSONS.md に 1 行残す
- 状態: 採用 / 日付: 2026-09-05

## 状況
初版の規則は「同じ指摘を 2 回受けたらスキルの『つまずきどころ』に足す」だった。だが 1 回目を覚えている主体がセッションをまたいで存在せず、実質「毎回が 1 回目」で何も残らない。口調や報告の仕方のようにスキルに紐づかない指摘は置き場も無かった。
## 決定
指摘を受けたその場で `scripts/ws lesson add "〜のとき、〜する（理由）"` でルートの `LESSONS.md` に 1 行残し（同じ行は重複させない）、SessionStart hook が起動のたびに全行を差し込む。案件固有は `--project <案件>` で案件 `index.md` の「この案件での決まりごと」へ。20 行を超えると `doctor` が報告するので、統合するか AGENTS.md・`doctor` の検査へ昇格して減らす。道具の落とし穴はスキルの「つまずきどころ」に残す。
## 理由
hook で差し込めば規約（AGENTS.md）を増やさずに済み、途中で足しても会話のキャッシュを壊さない。作者の環境の実測: 135 セッションの人の発言 1,034 件を指摘らしい 16 語で当てると 64 件、うち無作為に読んだ 22 件で指摘は 3 件（キーワード検知は精度不足）。auto-memory の feedback は 5 か月で 18 件（年に数十行で、種類別に分ける量ではない）。上限なしの lessons.md は 1,360 行に育ち障害記録が主になった（上限と昇格の圧力が要る）。
## 捨てた案
- 指摘のキーワード検知 hook・Stop hook での強制: 検知が外れの多い注意は無視されるようになる
- 種類別ファイル: 量が少ない上に、種類を付け忘れると差し込みが黙って空になる
## 影響
LESSONS.md は起動のたびにコンテキストに載る。長いほど守られなくなるので 20 行の上限を守る。指摘かどうかの判断はエージェント自身に委ねている。
