# 0029. 引用の照合（0028）は、原文と引用の両方から Markdown の記号を除き、括弧の中だけを見る
- 状態: 採用 / 日付: 2026-10-03

## 状況
0028 の照合を、テンプレートから作った実際の作業スペース（reference 243 本・「引用した記述」1,084 行）に当てると、227 行が「原文に無い」になった。手で確かめると本物のずれは約 37 件で、残りは書き方の違いだった（適合率 約 16%）。このままだと昇格のたびに大量の行が出て、エージェントが直しに回るターンが増える（0028 が避けたかったこと）。

誤検知の内訳（重なりあり）: 英語の引用を "…" で囲む（「」しか外していなかった）105、1 行に「A」「B」と並べる（greedy で 1 つにつないでいた）、"A" / "B" と並べる、原文の `[文字](URL)` 19、’ と ' ・ “ と " の違い、`[ ]`・表の `|`・`_` の有無、括弧の無い地の文（「〜は表のセルから読んだ」のような注記や見出し）を引用とみなした 180 行。

## 決定
- 原文と引用の両方を同じ関数で正規化する: リンク記法は文字だけ残す、`’‘“”` を ASCII にそろえる、空白・`*`・`` ` ``・`\`・`|`・`_`・`#`・`>`・`[ ]`・HTML タグ・文字どおりの `\n` を除く
- 引用は 1 行から「…」・“…”・行頭の "…" を全部抜き、" / " で並べたものは分ける
- 括弧の無い行は、`>` で始まる行だけを引用とみなす。それ以外の地の文は見ない

## 理由
同じ 1,084 行で「原文に無い」は 227 → 45 に減った。45 件を手で分けると、本物 30（言い換え・別のページからの引用・2 つのデータセットの数字の取り違え・設定名の取り違えなど）、表のセルの数字で原文に無いもの 7（おそらく本物）、誤検知 8（強調の「」・PDF の行末のハイフン・LaTeX・コード中の文字列の連結・脚注の URL・末尾の句点）。誤検知は引用 1,006 件の約 0.8%。

**訂正（2026-10-03、PR #40）**: 上の分類は誤り。この正規化の `<[^>]+>` が原文の `<`（比較演算子・数式）から次の `>` までを丸ごと消しており、45 件の分類も同じ正規化を通した原文で判定していたので、消された範囲にある正しい引用を「本物」と数えていた。タグを英字で始まり 1 行に収まるものに限ると 45 → 16 件で、消えた 29 件はどれも生の原文に一字一句あった。16 件の内訳は本物 約 9（別のページからの引用・2 つのデータセットの数字の取り違え・設定名の取り違え・言い換え）、誤検知 約 7（強調の「」3・末尾の句点・LaTeX・PDF の行末のハイフン・コード中の文字列の連結）。照合器の誤検知は、検査する正規化を通さず生の原文で判定する。

issue #36 の事故（12 か所）にも当てた。成果物の「引用: 「…」」を、その行の「出所:」が指すファイルと照合すると 6 か所（原文と不一致 4・出所違い 2）を誤検知 0 で拾う。ただし事故の引用はタスクの成果物にあり、出所は references ではなく knowledges だったので、0028 の照合（references だけを見る）では 1 か所も拾えない。

## 捨てた案
- 大文字小文字を無視する: 拾える行が 2 行増えるだけで、取り違えを見逃す側に倒れる
- 短い「」（5 字以下など）を見ない: 表の数字（「14.37」など）が本物のずれとして出ており、それを落とす
- 括弧の無い行も全部引用とみなす（0028）: 上の 180 行の誤検知

## 影響
地の文で語を「」で強調すると、まれに誤検知になる（「使いどころ」の 3 件）。括弧も `>` も無い引用は照合されない。タスクの成果物の引用（出所が knowledges や別ファイル）は、まだ照合していない。

根拠: issue #36、`tests/test_ws.py` の `test_quote_check_ignores_markup_and_notes`
