# 0034. 依頼の中の人の案は未検証の仮説として扱い、誤りなら手を動かす前に言う
- 状態: 採用 / 日付: 2026-10-25

## 状況
XYEval（arXiv 2609.23939v1、Google DeepMind ほか、2026-09）は、既存のベンチマークの課題文にもっともらしいが誤った案（「I think …」）を 1 文足し、5 モデル × 6 ベンチマークの 30 組中 29 組で成績が下がることを示した（最大は Terminal-Bench の −46.7%）。不適切な同意の 53.5〜89.3% は「検討せずに事実として受け入れる」型で、疑いを口にしながら従う型も 2〜19% ある。τ²-bench では思考の中で欠陥に気づいていても、23〜34% のトレースで利用者に伝えていなかった。agent-ws の規約には、人の依頼や指摘（`lesson add`）を確かめずに受け入れるのを止める文が無かった。

## 決定
AGENTS.md に「人の案を鵜呑みにしない」の節（4 行）を足す。依頼の中の案は未検証の仮説として扱い、効くかを確かめてから従う。誤り・筋が悪いなら手を動かす前に根拠と代わりの案を出す。気づいた欠陥は口に出す。新しい根拠の無い反論では意見を変えない。人が理由を聞いたうえで選んだら従う。報告と調査係への指示では仮説と確かめたことを分ける。「同じ失敗を繰り返さない」の `lesson add` にも、指摘が事実と合わないなら残す前に確かめる 1 文を足す。

## 理由
- 論文で効果を測った対策は system instruction だけで、一般的な警告（XY defense）は Gemini の 12 組中 11 組で低下を縮めた（τ²-bench の Gemini 3.1 Pro は −25.9% → −15.0%）が、SWE-bench Verified の Gemini 3.1 Pro は −10.9% → −11.1% で効かなかった。注入した案を名指しする指示（Golden defense）はほぼ 0 まで戻すが、どの案が誤りかを事前に知っている前提なので使えない。使える手は一般的な警告だけなので、規約の文として置く
- 失敗の主因が「検討しない」なので、警告ではなく「確かめてから従う」という手順で書いた。黙って従う・考えの中だけで気づく型が別にあるので、「言う」を別の文にした
- 逆向きの失敗（何にでも反対して人の決定を覆す）を避けるため、決めるのは人だと同じ節に書いた
- 調査係への指示に本線の見立てを書くと、調査係にとっての誤った案になる（論文の構造からの類推で、測っていない）

## 捨てた案
- UserPromptSubmit の hook で「〜と思う」「原因は」などの文を検出し、その文を名指しして注意を足す（Golden に寄せる案）: 日本語の言い回しの検出は誤検知が多く、名指ししても誤りかは分からないので Golden と同じ効果は期待できない。測っていない仕組みを毎ターンの経路に入れない
- 固定分を増やさない（0027・0028）ために規約に書かない: 守らせる手段が文しか無く、判断の要る行動なので doctor や hook で数えられない

## 影響
AGENTS.md の固定分が約 600 字増える。効果は agent-ws の bench で未測定で、論文の対策の測定も Gemini だけ（Claude・GPT では未確認）。
