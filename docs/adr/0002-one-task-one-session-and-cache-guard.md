# 0002. 1 タスク = 1 セッションにし、キャッシュが切れたあとの 1 通目は送らずに止める
- 状態: 採用 / 日付: 2026-09-05（Codex の 30 分は 2026-09-06）

## 状況
プロンプトキャッシュは一定時間で切れ、切れたあと同じ会話に続きを送ると会話全文を定価で再処理する。長い会話ほど払い直しが大きく、別のタスクを同じセッションで続けると文脈も混ざる。
## 決定
新しいタスクは新しいセッションで始める（Claude Code は `/clear`、Codex は新しいセッション）。Stop hook が応答時刻を記録し、UserPromptSubmit hook はしきい値以上空いた 1 通目を exit 2 で止めて `/clear` からの再開を案内する。しきい値は `WS_CACHE_TTL_MIN` → `--ttl` → 既定 60 分。Codex は `.codex/hooks.json` で `--ttl 30`。10 分以内の再送は通す。SessionStart hook が `/clear`・compact 後も現在のタスクを再注入する。
## 理由
Claude のサブスクリプションはキャッシュが 1 時間、API キー直叩きは 5 分（`WS_CACHE_TTL_MIN=5`）。Codex（GPT-5.6 以降）は `prompt_cache_options.ttl` の既定かつ唯一の値が `30m` で、最後の利用から 30 分の再利用が公式の保証。止めた時点では API が呼ばれず、実測で所要 208 ms・使用トークン 0。
## 捨てた案
- 警告文（systemMessage）だけ出す: 裏で定価の再処理リクエストが飛んでしまう
- `/loop` で空メッセージを送りキャッシュを延命する: 1 回ごとに全文のキャッシュ読み（定価の約 10%）が掛かり、一晩放置なら冷たく再開したほうが安い
- UserPromptSubmit で毎ターン現在のタスクを注入する: 履歴に積まれ、以降の全リクエストで送り直される
## 影響
続けたい 1 通が止まることがある（同じ内容を 10 分以内に再送すれば通る）。切れてほしくない環境は `promptCacheTtl: "1h"`（Claude Code 2.1.242 以降）で延ばせるが書き込み単価は上がる。`.codex/hooks.json` を変えたので Codex は `/hooks` で trust し直す。
