# 0023. 同梱の見本は scripts/ws init で消す。消すのは同梱時から内容を変えていないファイルだけ
- 状態: 採用 / 日付: 2026-09-19

## 状況
見本は `projects/_example/`（架空の案件。タスク・ナレッジ・オントロジー）と repo 直下 `knowledges/`（架空の自社の組織図・用語 3 語・オントロジー）の 2 か所、合わせて 21 ファイルある。消す手段が README の一文だけで、コマンドが無かった。置き換えを促す仕組みは共通ナレッジの 90 日警告（0015）だけで、`projects/_example/` には何も効かない。共通ナレッジの一覧は起動のたびに差し込まれるので、置き換えないままだと架空の組織図と用語が仕事に混ざり続ける。

## 決定
- `scripts/ws init` は見本を「パスではなく内容」で判定して消す。`templates/examples.json` に見本の「パス → sha256」の一覧を持ち、いまの内容がそのハッシュと同じファイルだけを消す。ハッシュはテキストとして読んでから取る（CRLF を吸収）
- 内容が違うファイル（利用者が書き換えたもの）と一覧に無いファイル（利用者が足したもの）は残し、実行結果に名前を出す
- 消したあと空になったフォルダを片付け、`projects/index.md` と `knowledges/index.md` を作り直す。手つかずなら `projects/_example/` と `knowledges/` はフォルダごと無くなる（`knowledges/` は `know new --common` / `glossary add --common` が雛形から作り直すので無くて困らない）
- git が無くても使える。消えるのは同梱物と同一の内容だけなので、テンプレートから取り直せる
- `scripts/ws init --manifest` はテンプレートの保守用で、見本を直したときに一覧を作り直す。`tests/test_init.py` が「同梱の見本 == 一覧」を検査するので、見本を直して一覧を忘れるとテストが落ちる
- SessionStart hook は、init で消せるファイルが 1 本でも残っている間だけ「同梱の見本が残っている。自分の仕事を始めるなら、人に確かめてから `scripts/ws init` で消す。見本を試している間はそのままでよい」の趣旨の 1 行を差し込む。init 済み・全部書き換え済みなら出ない。`bench/` の作業スペースには見本のパスが無いので出ない

## 理由
- 0015 は共通ナレッジの見本を「自社の事実に置き換える」と案内している。同じファイル名のまま中身が本物になっている利用者がいるので、パスでは見本かどうかを決められない。決められるのは内容だけ
- 内容が同梱時と同じなら、消えても失うものが無い（テンプレートに同じものがある）。だから確認の問い合わせも、git の状態の検査も要らない
- 促す 1 行の条件を「init が消せるファイルがあるか」と同じ判定にすると、見本を全部書き換えた利用者には出なくなり、止めるためのフラグが要らない

## 捨てた案
- 決め打ちのパスを消し、未コミットの変更があれば拒否: 0015 の案内どおり同じファイル名のまま本物に書き換えた利用者の、コミット済みの組織図・用語集を作業ツリーから消してしまう
- `project new` で自動削除: 暗黙の削除。見本を横に置いて始めたい利用者を妨げる
- GitHub Actions で生成先の初回 push 時に消す: clone だけの利用・Actions 無効の環境で効かない。リモートにコミットが勝手に増える
- 見本を `examples/` へ移して配布: 起動直後に動く見本と README の実行例を失う
- 見本に印を付ける（`sample: true`）: JSON に付けられない。書き換えて印を消し忘れると本物が消える

## 影響
`templates/examples.json` の保守が要る（見本を直したら `init --manifest`。忘れると `tests/test_init.py` が落ちる）。0015 の「書き換えて使う」道は残る。SessionStart の差し込みは見本が残っている間だけ 1 行増える。`bench/` には影響しない。
