# 0022. 業務のオントロジーは「業務を動かす層」として入れる。定義は JSON、解釈と強制は scripts 側（0014 を置き換え）
- 状態: 採用 / 日付: 2026-09-17

## 状況
0014 は「重い層は入れず、用語集の関係列と frontmatter の任意欄を足して、埋まるかを実務で見る」だった。見直すと、その欄を読んで使う処理が `scripts/ws` に 1 つも無く、誰も読まない欄には埋める理由が無い。欄では、型と実体の区別・つながりの両端と件数・機械が判定する前提条件のどれも表せない。0014 が「止める対象が無い」とした前提も違っていた。文書を書く仕事にも、置き換え済みの台数の決定を前提にした見積・決裁の上限を超える見積・期限の切れた単価・担当の取り違えのように、機械が止められる誤りがある。

## 決定
- 定義の正本は JSON（`knowledges/ontology/` が自社共通、`projects/<案件>/knowledges/ontology/` が案件）。書けるのは 型とプロパティ・つながりの両端と件数・型の継承・アクション（引数・前提条件・ルール・承認）・定数
- 解釈は `scripts/wsonto/`（標準ライブラリだけ）。アクションは 引数の検査 → 前提条件 → 実体の写しに適用 → 制約の検査 → 承認の要否 → 反映と記録。どこで落ちても実体は変わらない。前提条件と計算は Python の式の部分集合を `ast` の許可リストで評価する
- エージェントは実体・記録・実行待ちのファイルを直接読み書きできない（PreToolUse）。読むのは `ws onto query / show`、変えるのは `ws onto act` だけ
- 承認の既定は実行待ち。承認できるのは人だけで、経路は人の発言（UserPromptSubmit が「承認 P-0001」を拾う）か端末。承認時は今の状態で検査をやり直す
- 定義の変更も `define apply` → メタモデル検査 → lint（公開されているアンチパターンのうち機械で見られるもの）→ 既存の実体との整合 → 実行待ち → 人の承認で版が上がる
- すべて `log.jsonl` に残し、実体のハッシュを鎖にして、アクションを通さない書き換えを doctor が見つける
- 定義は JSON Schema・Turtle（RDFS/OWL＋SHACL）・Mermaid に書き出せる。語彙の両端は `rdfs:range` でなく `schema:rangeIncludes` で書く。用語集の「関係」列と `relates_to` / `supersedes` は残すが案内から外す。起動時の注入はナレッジ一覧の 1 行だけ

## 理由
- 前提条件を機械が検査する・承認と記録を残す、は参照した設計（#5〜#7・#10）が中心に置く部品で、エージェントの注意力に頼らない（0001 と同じ考え方）。型の合った誤った呼び出し（8 台の決定の id を正しい型で渡す）は、引数の型では止まらない。実体の値を見る前提条件でしか止まらない
- W3C の標準を正本にしない理由: 前提条件と承認つきの操作を表す語彙が無い。OWL は開世界で「今このデータがこの形か」の検査に向かない。代わりに書き出して、自前の検査と pySHACL が同じ判定を出すことをテストで確かめる（`tests/test_onto_parity.py`）。`rdfs:range` は推論規則なので、推論つきの検査で型違いのリンク先に型が付き `sh:class` が効かなくなる（`tests/test_onto_w3c.py` で実測。#11・#12）
- 定義を LLM が書く前提なので、検収と人の承認を挟む（#8・#9）

## 捨てた案
- **用語集の列と frontmatter に寄せる**（0014 の任意欄の延長）: 上の 3 つが表せず、前提条件がエージェントの自己申告になる
- **RDF/OWL/SHACL や LinkML を正本にする**: 操作が表せない。追加パッケージが要り導入が重くなる
- **実体を SQLite に置く**: git で差分が読めず、人のレビューが成り立たない。1 万件を超えたら索引として再検討
- **MCP サーバーで公開する**（後で薄い皮として足せる。先に入れると固定分と導入手順が増える。0012）／**利用者が任意の Python 関数を登録できるようにする**（エージェントが書き換えれば前提条件を迂回できる）

## 影響
`scripts/wsonto/`・`scripts/ws onto …`・hook の拒否 3 種・`doctor` と `transcript normalize` の接続・スキル ontology-define・見本（共通と `_example`）。エージェントの正確さとトークンへの効果は未計測（照会と実行は 1 回ずつターンを増やす）。bench の制約シナリオは「定義＋解釈」の条件で測り直す。取り決めは `scripts/wsonto/README.md`。
