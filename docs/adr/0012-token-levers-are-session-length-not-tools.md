# 0012. トークンを減らす手段はセッション長だけ。索引・グラフ・出力圧縮のツールは入れない
- 状態: 採用 / 日付: 2026-09-08

## 状況
「トークンを減らすツール」を外に探した。発端は tgrep（トライグラム索引付き grep）を組み込む価値があるかで、実測すると tgrep と ripgrep は出力がバイト単位で同一だった（644,743B・469,975B・2,048,951B の 3 クエリで一致）。速くはなるがトークンは 1 文字も減らない。そこから検索・索引・グラフ・出力圧縮・コンテキスト圧縮プロキシを 16 本以上調べた。

## 決定
外部ツールは入れない。トークンに効く手段は「セッションを長くしない」ことだけと結論し、既存の「1 タスク = 1 セッション」（0002）を根拠つきで維持する。MCP を積まない判断（tool search の項）はトークンを理由にしない。

## 理由
消費はセッション長に対して線形ではなく 2 乗で伸びる。実セッション 20 本・847 ターン・1.63 億トークンの当てはめで `総トークン ≒ 39k × ターン数 + 1,848 × ターン数²`（R² 0.976）。LangWatch の独立集計（2,451 セッション・287,748 API コール）も指数 2.55・R² 0.994 で一致する。tool 結果の本文は総消費の 0.2〜3.1% しかなく、出力を縮める道具が触れる範囲がそもそも狭い。

第三者が対照実験で測った削減ツールは 4 本だけで、3 本が否定的だった。rtk は JetBrains の測定で低 effort +7.6% 割高（p=0.004、ターン +13.8%・cache read +14.3%）、Caveman は主張 65% に対し実測 8.5%、Graphify は KubeNine の独立検証で節約ゼロ（$74.89 → $85.88）。grepai は新規入力を 97% 減らして費用が 27.5% しか下がらず、ベンチ自身が「両条件とも cache read が総消費を支配していた」と書いている。

グラフ・オントロジー系は tool call を確かに減らす（46→18、58→7）が、セッション総トークンでは負ける。RepoGraph（ICLR 2025）が査読付きで、ターン 21.47→19.12（−11%）に対しトークン 245,008→262,512（**+7%**）を示している。ツール定義とグラフ出力が毎ターンの固定分に乗り、ターン削減を食い潰す。同じ形の否定的実測が samchon（serena +93%、CodeGraph +22〜47%）にもある。

## 捨てた案
- **tgrep**: 出力が rg と同一。トークンは減らない。速さは agent-ws の規模（17MB・2,755 ファイル）では 1 クエリ最大 15ms
- **MCP を減らす**: Claude Code 2.1.x は tool search（deferred tools）が既定オン。実測で 28 本積んで 1,313 トークン/ターン、`ENABLE_TOOL_SEARCH=false` で切ると 49,409 → 78,512 に増える。**減らす余地はもう無い**
- **mcp-compressor 等のツール定義圧縮プロキシ**: tool search と役目が重複し、第三者実測も無い
- **rtk 等の出力圧縮**: 理論上の天井が 9%（JetBrains の独立計算では ≒3%）、実測は逆効果
- **グラフ／オントロジー MCP**: 上記のとおりターンは減るがトークンは増える
- **context editing / memory tool / サーバサイド compaction**: API 側には効く仕組みがあるが Claude Code から使えない（バイナリに `clear_tool_uses` の文字列 0 件）。自作ハーネスを書くなら本命

## 影響
`AGENTS.md` の「1 ターン ≒ 32k」を実測の 39k に更新し、2 乗で伸びることを書き足した。`README.md` の「自動 compact を早める」節に、これまで「測っていない」としていた損益分岐の数字（最小点 220,000 トークン、110k 未満は逆効果、compact 直後の訂正率 17.7%→41.9%）を入れた。委譲の 4 条件（0008）は変えない。サブエージェントは親の deferred tool loading を継承せず起動時点で 140〜180k を食うという報告（claude-code issue #60141・Closed as not planned）があるので、条件を緩めるときはそこを測ってからにする。

Claude Code のバージョンが上がるとハーネス側の固定分（毎ターン必ず送られる分）が動く（bench 当時 32k → 実測 39k）。数字を引くときは測り直す。
