# 0031. arXiv の論文は PDF ではなく HTML 版を本文にし、版で固定して保存する
- 状態: 採用 / 日付: 2026-10-03

## 状況
論文を引用するときは一字一句の一致が要る（0028〜0030 の照合）。arXiv の PDF の URL を `ref add` に渡すと、PDF のバイナリがそのまま `.orig.md` になり読めなかった（19MB のファイルができた例がある）。PDF からテキストを抜くと、2 段組の行の混ざり・行末のハイフン・合字・数式の崩れが起きる。arXiv は LaTeX から作った HTML 版（arxiv.org/html/<id>）と LaTeX ソース（arxiv.org/e-print/<id>）を配っている。

## 決定
- `ref add` が arXiv の URL（abs・pdf・html・e-print）を受け取ったら、arXiv API で版と投稿日を取り、版で固定した HTML 版を本文として保存する。タイトルに `（arXiv <id>v<N>・<投稿日> 投稿）` を付ける
- HTML 版が無い（404）・変換エラー（`ltx_ERROR`）があるときは、LaTeX ソースの .tex を全部つないで別の reference に保存する。無いときは、そのコマンドで取れることを案内する
- HTML の抽出で MathML の `annotation`（LaTeX の原文）と目に見えない演算子（U+2061〜2064）を捨てる。残すと `n=20n{=}20`・`Φ⁡(` になる
- arXiv 以外の PDF の URL は止める。PDF しか無いときの手順（`-layout` なしの pdftotext、抜けたページだけ画像で見て別の reference にする）は paper-read スキルに書く。AGENTS.md は変えない（0027）

## 理由
- 2609.01038v1 を別の作業スペースで人が作った引用の台帳（PDF を `pdftotext -layout` で抜いて読んだもの）から、表を除く引用 64 件（`...` で切った断片）を、空白とハイフンを除いて照合した。一致は HTML 版 49、PDF（`-layout` なし）45、PDF（`-layout`）0。`-layout` は左右の段の行が 1 行に並ぶので、段をまたぐ文が一致しない
- HTML 版で外れた 15 件の内訳: 数式（分数の `/` が消える、`δ̂` が `δ^`、二項係数が `(1002)`）6、台帳の引用が囲み（Takeaway）や段落をまたいでいる 4（PDF でも一致しない）、HTML 版で文の並びが PDF と違う 1、台帳の側で `’` を `'` に打ち直している 2、参考文献 1、脚注の番号が本文に混ざる 1。PDF でも数式は一致しないので、数式は LaTeX ソースで確かめる
- r.jina.ai は arXiv の HTML 版に図の説明文 331 バイトしか返さなかった（2026-10-03）。既存の 500 バイトの判定で直接取得に落ちたが、境目の上で壊れた本文を返しうるので arXiv は直接取る

## 捨てた案
- PDF を本文にしてページ番号で引用する: 上の照合で HTML 版より一致が少ない。HTML 版には節番号があり、出所は節で書ける
- 常に LaTeX ソースも取る: 図を含むアーカイブは数十 MB になりうる。本文の引用には要らない
- 抜けたページの検出と画像からの書き起こしを `ref add` に入れる: arXiv では要らない。arXiv 以外の PDF が来た頻度を見てから決める

## 影響
図の中の文字は HTML 版にも LaTeX ソースにも無い。図から値を読むときは人に PDF を置いてもらう。HTML 版にはページ番号が無いので、出所は節番号で書く。
