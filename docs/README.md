# docs/ — agent-ws 自体の設計判断と規則の根拠

ここは **agent-ws を保守する人のための場所**で、案件の仕事には使いません。
規約や hooks を書き換える前に、`adr/` で「なぜそうしたか・何を捨てたか」を確かめてください。
AGENTS.md や README に書いた規則と数字（「安いモデルへ委譲する 4 条件」「Codex のキャッシュは 30 分」「compact 後に再読されるのは直近 5 ファイル」など）が、
どのページのどの一文から来たかを残しています。ページは書き換わるので、規則を見直すときに撮り直して差分を見られるようにするためです。

| 場所 | 中身 | 読む人 |
|---|---|---|
| `adr/` | 設計判断の記録（状況・決定・理由・捨てた案・影響。1 本 20 行以内）。一覧は [adr/README.md](adr/README.md) | 規則を変える人 |
| `sources/` | 規則の根拠台帳。`delegation.md`（委譲規則）と `token-saving.md`（トークン節約 5 点）。出典・取得日時・ファイル・支えている規則 | 規則を変える人 |
| `snapshots/` | 出典ページの原文。`ref add` と同じ形で、要点 `<name>.md`（引用した記述・使いどころ）と原文 `<name>.orig.md` の対 | 台帳から辿るときだけ |

## 使い方

- 規則を足す・変えるときは、根拠のページを `WS_ROOT=$PWD uv run python scripts/ws ref add <URL> --dir docs/snapshots --summary "<1文>"` で撮り、
  要点ファイルの「引用した記述」に原文のままの一文を、「使いどころ」にどの規則を支えるかを書き、`sources/` の台帳に 1 行足す。
- 撮り直すときも同じコマンド。台帳のファイル欄を新しい名前に差し替える。古い対は消してよい（git に残る）。

## 案件の仕事では読まない

`snapshots/` の原文は数十 KB〜200 KB あり、案件の仕事で grep が当たると丸ごと読んでしまうので、
現在のタスクがある間は hook が `bench/` と同じく拒否します。台帳（`sources/`）は読めます。
テンプレートから自分の作業スペースを作った人は、`snapshots/` を消して構いません（台帳だけ残せば出所は分かります）。
