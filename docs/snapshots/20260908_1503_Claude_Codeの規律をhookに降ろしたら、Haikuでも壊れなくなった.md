# Claude Codeの規律をhookに降ろしたら、Haikuでも壊れなくなった

## 引用した記述（原文のまま。要約しない）
- 重要なのは、**exit 2で終了すると、stderrの内容がそのままエージェントにフィードバックされる**ということです。つまり人間には何も通知されず、編集した本人(エージェント)にだけ「ここがダメ」と返ります。これが編集のたびの自動レビューとして機能します。
- プロンプトのルールは「読まれて、覚えられていて、その瞬間に想起される」ことが条件となっています。hookはgrepなので、セッションが50万トークン目だろうが、軽量モデルだろうが必ず発火します。
- プロンプトにルールを置くと、守られていても毎回そのトークンを払います。hookは逆で、**違反しなければ0トークン**です。
- 境界線はシンプルで、**偽陽性なく機械判定できるならプロンプトからhookへ降ろす、判断が要るならプロンプトに残す**です。

## このタスクでの使いどころ（使わなかったなら理由）
kanban T-6PJJT で agent-ws の強化案を出す根拠。agent-ws は既に hook 中心の設計だが、
`PostToolUse` は `matcher: WebSearch` だけで、**書いた直後に検査する経路が無い**。
一方 `doctor` は同じ検査（summary の欠落・引用の未記入・参照ナレッジの陳腐化・LESSONS の20行超）を
持っているのに、誰かが叩かないと発火しない。この記事の言う「常時課金から違反時のみ課金へ」を
そのまま当てはめると、doctor の検査を `PostToolUse`（Edit/Write）に降ろして exit 2 で返す形になる。
著者の実測値（発火率100%・差し戻しループの減少）は ccteams というツールでの報告であり、
agent-ws で同じ効果が出るかは未測定。

第三者の報告として引く（帰属）。同記事のモデルプロファイル（builder/reviewer の一括リマップ）は
agent-ws には採らない — サブエージェントは researcher 1体だけで既にモデルが固定されているため。
