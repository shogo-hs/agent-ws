## はじめに

以前[Claude Codeのプロンプトキャッシングについて記事](https://zenn.dev/studist/articles/01-claude-code-skill-cached-token-analysis)を書きました。

 今回は実践編になります。

 といってもかなり雑な実験なので話半分に読んでください(とても太くて強固な予防線)

僕はStudistでのインターンを始めて3ヶ月と、まだまだ既存のプロダクトのことはわからないことだらけです。

 そのため高頻度でClaude Codeにプロダクトの調査を投げがちなので、何回も同じことを調査させなくていいよう調査結果をNotionに保存させています。

 一方で常々気になっていました。

**「調査→結果出力→Notionにも出力」って二度手間じゃない？token、勿体なくない？**

**でもキャッシュされてるならそんなに二度手間じゃない...？**

 そう思った僕の目の前には1時間前にNotion化まで完了したセッションが！これは試すしかない！

ということで以前の記事執筆時の知見を活かし、調査完了後即Notionを書かせた場合とある程度時間を置いてから書かせた場合でトークン消費を比較してみました。

本記事では、**実際のセッションログを詳細分析**して、以下を明らかにします：

*   Claude Codeの実際のトークン消費量とコスト内訳
*   プロンプトキャッシングの効果
*   **キャッシュ有効期限（5分/1時間）が料金に与える影響**
*   コスト最適化のための実務的な推奨事項

## TL;DR

*   **キャッシュが有効な間に作業を完了すると、コストを1/7に削減できる**
*   Notion書き出し: キャッシュ有効時$0.49 → 1時間後$3.65（**7.5倍**）
*   キャッシュ再利用率: 97.4% → 64.5%（キャッシュ期限切れ時）
*   **連続作業を心がけることでコスト効率が大幅に向上**

## 分析対象のセッション

以下のような2フェーズのタスクに対してパターンを2つ用意して実験しました。

タスク:

1.   **調査フェーズ**: ユーザー状態保存手段（localStorage vs サーバーサイド等）の比較検討
2.   **Notion書き出しフェーズ**: 調査結果をNotionページにまとめる

パターン:

*   セッション1: フェーズ1(調査フェーズ)実行後すぐにフェーズ2(Notion書き出しフェーズを実行)
*   セッション2: セッション1のフェーズ1完了時点からキャッシュが全て切れるまで待ち、その後フェーズ2を実行

## 🔬 実験設計のポイント

**セッション2は `/fork` 機能を使用:**

*   セッション1の調査完了時点からフォーク
*   76分間待機してキャッシュを意図的に期限切れにした状態でNotion書き出しを実行
*   (~/.claude/projects/を編集してNotion化の部分のログを削除)

これにより調査部分は完全に同一。Notion書き出し部分のみが異なる完璧な比較実験が実現。

## 料金体系（Sonnet 4.5の場合）

| 項目 | 料金（USD / 100万トークン） | 倍率 |
| --- | --- | --- |
| 基本入力 | $3 | 1.0x |
| 基本出力 | $15 | 5.0x |
| **キャッシュ読み込み** | **$0.30** | **0.1x** |

**重要なポイント:**

*   キャッシュヒット時は**通常の1/10のコスト**（$0.30 vs $3）
*   キャッシュ作成は2倍のコスト（$6 vs $3）だが、再利用で元が取れる設計

## Notion書き出しフェーズのコスト比較

| 指標 | キャッシュ有効 | 76分後 |
| --- | --- | --- |
| **総コスト** | **$0.49** | **$3.65** |
| キャッシュ読み込み | 1,069K | 621K |
| キャッシュ作成 | 28K | 342K |
| 再利用率 | 97.4% | 64.5% |

## セッション全体のコスト比較

| 項目 | セッション1 | セッション2 | 差分 |
| --- | --- | --- | --- |
| 調査コスト | $3.15 | $3.15 | $0（同一） |
| Notion書き出し | $0.49 | $3.65 | **+$3.16** |
| **総コスト** | **$3.64** | **$6.80** | **+$3.16 (+86.8%)** |

### 📊 重要な発見

1.   **調査フェーズのコストは両セッションで完全一致（$3.15）**

    *   **セッション2は `/fork` で分岐したため、調査部分は全く同じデータ**
    *   フォークにより「他の条件は同じで、タイミングだけ変えた実験」が実現
    *   これが完璧な比較実験を可能にした

2.   **Notion書き出しフェーズで7.5倍の差**

    *   実質的な作業コスト（入力+出力）: 約$0.0007（ほぼ同じ）
    *   キャッシュ関連コスト: $0.488 → $3.649（**差額$3.16**）
    *   **同じ作業でもタイミングだけでこれだけの差が発生**

3.   **原因: キャッシュ有効期限切れ**

    *   調査終了: 08:40:52
    *   Notion書き出し開始: 09:56:56
    *   **経過時間: 76分（1時間16分）**
    *   → 1時間のキャッシュも期限切れ

## キャッシュ有効期限の仕組み

Claude Codeでは2種類のキャッシュが使用されます。

| キャッシュタイプ | 有効期限 | 料金 | 用途 |
| --- | --- | --- | --- |
| `ephemeral_5m` | **5分** | $3.75 / 100万 | 短期的な会話 |
| `ephemeral_1h` | **1時間** | $6 / 100万 | 永続コンテキスト |

*   [プロンプトキャッシングについて](https://docs.anthropic.com/en/docs/build-with-claude/prompt-caching)

## キャッシュ期限切れ時の挙動

1.   **キャッシュが有効な場合:**

```
ユーザー入力
→ キャッシュ読み込み（$0.30/100万）
→ 新規部分のみキャッシュ化
``` 
2.   **キャッシュ期限切れ時:**

```
ユーザー入力
→ すべてのコンテキストを再構築
→ 全体をキャッシュ化（$6/100万）
```

## 🎯 実践のポイント

Claude Codeを使う際は、**「キャッシュを味方につける」**ことを意識しましょう。

特に大規模なタスクや関連する複数のタスクは、できるだけ連続して実行することで、コスト効率が大幅に向上します。

## 実践：自動警告フックの実装

今回の分析結果を活かして、**キャッシュ期限切れを自動検知する警告フック**を実装しました。

## 🎯 実装の目的

うっかりキャッシュが切れた状態でNotion書き出しを実行してしまうと、**約7.5倍のコスト増加**（$0.50 → $3.65）が発生します。

これを防ぐため、UserPromptSubmitフックで自動的にチェックし、ユーザーに警告する仕組みを作成しました。

## 📝 実装内容

### 動作フロー

```
ユーザー: Notion URLを含むメッセージを送信
    ↓
フック: 前回のメッセージから5分以上経過？
    ↓
【5分以上経過の場合】
    ↓
1. macOSアラートを表示
2. exit 2でプロンプト送信をブロック
    ↓
ユーザー: アラートを確認
    ↓
続行する場合: "timing-check:ignore" を追加
    ↓
フック: bypass検出 → exit 0（送信許可）
```

### 核心コード

check-notion-timing.sh

```
#!/bin/bash
# UserPromptSubmitフック

# stdin からユーザーのプロンプトと会話履歴パスを取得
INPUT=$(cat)
PROMPT=$(echo "$INPUT" | jq -r '.prompt')
TRANSCRIPT_PATH=$(echo "$INPUT" | jq -r '.transcript_path')

# Notion URLをチェック
if ! echo "$PROMPT" | grep -q "notion.so"; then
  exit 0
fi

# bypass フレーズをチェック
if echo "$PROMPT" | grep -qiE "timing-check:ignore"; then
  exit 0
fi

# 前回のメッセージのタイムスタンプを取得
LAST_TIMESTAMP=$(jq -r 'select(.type == "user") | .timestamp' "$TRANSCRIPT_PATH" | tail -1)

# 経過時間を計算（Python3でISO 8601をパース）
ELAPSED=$((現在時刻 - 前回時刻))

# 5分（300秒）以上経過している場合
if [ $ELAPSED -gt 300 ]; then
  MINUTES=$((ELAPSED / 60))

  # アラート表示
  osascript -e "display alert \"⚠️ キャッシュ期限切れ\" message \"前回から${MINUTES}分経過

バイパスフレーズ: timing-check:ignore\" as critical"

  # プロンプト送信をブロック
  exit 2
fi
```

## 💡 設計のポイント

### 1. **トークン消費ゼロ**

*   ❌ 従来: stdout → Claudeのコンテキスト → トークン消費
*   ✅ 今回: osascript → 直接アラート → **トークン消費なし**

### 2. **UserPromptSubmitフックの活用**

Claude Codeの`UserPromptSubmit`フックは、ユーザーがメッセージを送信する直前に実行されます。

**利用可能な情報:**

```
{
  "prompt": "ユーザーが送信したテキスト",
  "transcript_path": "/path/to/session.jsonl",
  "session_id": "abc123",
  ...
}
```

この`transcript_path`から会話履歴を読み取り、前回のメッセージのタイムスタンプを取得できます。

### 3. **exit 2でブロック**

```
exit 0  # プロンプト送信を許可
exit 2  # プロンプト送信をブロック
```

`exit 2`を返すことで、ユーザーのメッセージ送信をキャンセルできます。

### 4. **bypass機能**

意図的にキャッシュ期限切れを無視したい場合：

```
https://www.notion.so/page にまとめて timing-check:ignore
```

メッセージに`timing-check:ignore`を追加すると、警告をスキップして送信できます。

## 📊 効果

| 項目 | 内容 |
| --- | --- |
| **防止できるコスト増加** | 最大$3.16 / 回 |
| **トークン消費** | 0トークン（osascriptで直接通知） |
| **誤検知** | bypass機能でスキップ可能 |
| **実装コスト** | 約70行のシェルスクリプト |

## 🔧 設定方法

`~/.claude/settings.json`に以下を追加：

```
{
  "hooks": {
    "UserPromptSubmit": [
      {
        "hooks": [
          {
            "type": "command",
            "command": "~/.claude/commands/check-notion-timing.sh"
          }
        ]
      }
    ]
  }
}
```
