# AI駆動開発のためのオントロジー

## 引用した記述（原文のまま。要約しない）
- 「AIエージェントが物事を判断する際には、LLMの推論による判断と、データモデルによる決定的な判断という、二つの判断軸が存在します。」
- 「これまでRAGやスキルで制約をかけることも行われてきましたが、テキストベースの制約では、複数の文書にまたがる関係や制約までは保証しにくいという課題があります。」
- 「一見、オントロジーの定義がオーバーエンジニアリングに見えるかもしれません。」
- 「しかし、オントロジーとして定義する最大の価値は、**「そのルールを機械的に検証・追跡できるデータとして永続化できること」** にあります。」
- 「> Cost warning: Neptune + OpenSearch Serverless cost ~$930/mo when idle. Destroy stacks when not actively testing」（記事が AWS のドキュメントから引いた部分）

## このタスクでの使いどころ（使わなかったなら理由）
ADR 0014 の「状況」と「理由」。オントロジーが解く問題を「語の固定・関係の辿り・制約の機械的ゲート」に分解する出発点にした。記事の主張の核（機械的に検証できるデータとして永続化する）は、agent-ws では hook の拒否（ADR 0001・0010）と knowledges/ の単一正本（ADR 0004）が既に担っていると判定した。数字（930 ドル/月）は記事の引用をそのまま使い、AWS 側の原文は #3 で確認できなかった（README には載っていない）。
