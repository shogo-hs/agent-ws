# paper-read

ゴール: 論文の本文が一字一句のまま references/ に残り、要点と引用が原文と突き合わせ済みの状態。

## 既定の進め方
1. arXiv なら、渡された URL の形（abs・pdf・html）のまま `scripts/ws ref add <URL>` を叩く。PDF ではなく、arXiv が LaTeX から作った HTML 版を本文として保存する。版（v1 など）と投稿日はタイトルに入り、URL も版で固定される。HTML 版が無い・変換エラーがあるときは LaTeX ソースも自動で保存される。
2. 通読と要約は researcher に渡す（AGENTS.md の 4 条件に当たる）。渡すのは保存された `.orig.md` のパスと、成果物の書式 `出所: <reference のファイル名> 引用: 「原文のまま」`。節番号（「3.1 Problem Formulation」など）を添えさせる。HTML 版にはページ番号が無い。
3. 戻った成果物の引用を `scripts/ws doctor` で原文と照合する（ADR 0030）。合わない引用は本線で原文を見て直す。
4. 数式と表は HTML 版で崩れる（分数の `/` が消える、`δ̂` が `δ^` になる、表の結合セルがほどける）。数式・表の数値を使う前に `scripts/ws ref add https://arxiv.org/e-print/<id>` で LaTeX ソースを保存して確かめる。
5. 図の中の文字は本文に無い。図はキャプションと本文に書かれた分だけを使う。図から値を読み取る必要があれば、人に PDF を置いてもらい、Read でそのページを見る。読んだ値は「図から読んだ」と書き、本文の引用と分ける。

## PDF しか無いとき（arXiv 以外、または PDF だけの投稿）
1. PDF のファイルを手元に置く（`ref add` は PDF の URL を受け付けない。人に落としてもらう）。
2. `pdftotext x.pdf x.txt` で抜き、`scripts/ws ref add x.txt --title "<論文名>（PDF から抽出）"` で保存する。`-layout` は付けない（2 段組の左右の行が 1 行に混ざり、引用が一字一句で一致しなくなる。ADR 0031 の実測で 64 件中 0 件）。
3. 抜けたページを機械的に探す: `pdftotext -f N -l N x.pdf -` の文字数が 200 字未満（スキャン画像）、または `(cid:` が出る（フォントの対応表が無い）。
4. そのページだけ `pdftoppm -r 100 -f N -l N -png x.pdf /tmp/page` で画像にして Read で見て書き起こし、`--title "<論文名> p.N（画像から書き起こし）"` で別の reference にする。抽出したテキストを上書きしない（画像からの書き起こしは言い換えや補いが混ざっても気づけない）。

## つまずきどころ
- r.jina.ai は arXiv の HTML 版に図の説明文しか返さない（2026-10-03 に 331 バイト）。`ref add` は arXiv だけ直接取るので、URL を自分で r.jina.ai に通さない。
- 台帳に引用を写すときに `’` を `'` に打ち直すと照合で外れる。原文からコピーする。
